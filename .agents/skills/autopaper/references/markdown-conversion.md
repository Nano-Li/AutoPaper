# MinerU conversion

Use this reference only for PDF-to-Markdown conversion and resuming that stage.

## Configuration and scope

- `config/mineru.example.toml` is the public template. Personal token/settings belong only in `config/mineru.local.toml` (already covered by Git ignore). Never print the token or signed storage URLs. Do not modify existing search/screening criteria to enable conversion.
- Run from the repository root using its Python environment. Use `--config` to select the same workflow database as the approved PDF downloads, including when a run-specific workflow config was used.
- Conversion sends local PDFs to MinerU. A user request to convert them authorizes this upload within the requested scope; merely requesting downloads/status does not.
- Defaults: serial papers, pipeline model, English, OCR disabled, direct network, polling every 10 seconds, 30-minute wait per paper. Network settings are independent of OpenAlex and Edge; do not change Clash automatically.

## Commands

```powershell
# Count the eligible queue without contacting MinerU
.venv\Scripts\python.exe -m autopaper.mineru --dry-run

# One-paper smoke test (choose an actual downloaded ID from the selected DB)
.venv\Scripts\python.exe -m autopaper.mineru --paper-id P0001 --limit 1

# Convert pending papers and resume processing tasks
.venv\Scripts\python.exe -m autopaper.mineru

# Explicitly retry failed items as well; existing remote tasks are reused
.venv\Scripts\python.exe -m autopaper.mineru --retry-failed
```

Optional arguments: `--config <workflow.toml>`, `--mineru-config <private.toml>`, `--paper-id P0001 P0002`, `--limit N`. Windows users can double-click `scripts/windows/convert_markdown.bat`, which asks for confirmation before uploading the pending queue.

## State and resuming

- Only `download_status = downloaded` with Markdown `pending` / `processing` is selected normally. Completed papers are skipped, including when their IDs are explicitly passed. Failures are selected only with `--retry-failed`.
- SQLite `mineru_jobs` stores the paper ID, PDF SHA-256, parser options (without token), remote batch ID, temporary upload URL, output location, and last error. The temporary signed URL is cleared after upload. This table and all artifacts remain local.
- Each upload is checkpointed. Interrupted polling and result downloads reuse the remote batch. A wait timeout keeps `processing`; rerun normally. A network error keeps the checkpoint but marks `failed`; rerun with `--retry-failed`. A confirmed remote parsing failure creates a fresh attempt only on explicit retry.
- A lock prevents concurrent conversion processes for the same database. Changed source PDFs or parser options are refused on resume; restore the original input/options rather than silently reusing incompatible output.
- A remote request accepted immediately before a crash but before its batch ID is saved cannot be recovered automatically; check the MinerU dashboard before retrying if this occurs. Expired upload URLs/tasks need manual diagnosis; do not loop resubmissions or retries indefinitely.
- HTTP authentication/quota errors stop the current run. Failed work never becomes `done`.
- Each result is kept under `paper_inbox/markdown/<journal>/<year>/<paper-id>-<attempt-id>/`, retaining the provider's Markdown, images and JSON. Original PDFs in the result archive are omitted. The main Markdown must be nonempty; archive paths are validated. SQLite records the actual Markdown path. Different attempts never overwrite previous output.
- The initial integration processes ordinary paper PDFs as whole files; it does not implement upstream's long-document splitting/merging. Honor MinerU's current file/page limits rather than silently truncating.

Use compact counts and the relevant paper IDs to report progress. `STATUS.md` is regenerated by the program after each paper; do not load all converted documents to count or summarize them. Do not touch historical review files during conversion.

API flow reference: [Nano-Li/minerU-kit](https://github.com/Nano-Li/minerU-kit), revision `db9e99b22f4418435392ef9ed0a422f111d96478`; [MinerU official API](https://mineru.net/apiManage/docs). AutoPaper's adapter is self-contained and does not require cloning this reference project to run.
