# AutoPaper

Operate inside the AutoPaper project. Treat the database selected by `[workflow].database` as the source of truth. The current `workspace/review.md`, timestamped review archives, `workspace/STATUS.md`, and their statistics are deterministic program output: never have the main Agent compose them from accumulated screening results or load their full contents into its context. Keep them synchronized at user-visible checkpoints, but do not add report inspection or redundant render calls between screening waves.

## Workflow

1. Read `config/config.local.toml`. Never print or copy API keys into reports, prompts, or logs.
2. Search with the existing OpenAlex pipeline. Import `candidates.jsonl` or `candidates.csv` with `python -m autopaper.workflow import`; do not read a large candidate file into the main Agent's context. Read [the screening database contract](references/screening-database.md) before importing.
3. By default, let the import command compare every candidate against the durable database by normalized full journal name plus title. Report only its compact counts: current candidates, existing matches, reused decisions, and papers still requiring Sub Agents. The command programmatically places reusable results in the current `review.md`. Never have the main Agent perform this matching or copy reused records. Use `--no-reuse` only when the user explicitly asks to ignore stored decisions and rescreen every current candidate.
4. If the configured criteria and decision prompt do not match the profile stored in the selected database, or if multiple candidate databases/profiles are available and the intended one is not explicit, stop and ask the user whether to reuse one and which one. Never mix decisions produced under different prompts. A new prompt should normally use a new database path.
5. Screen every remaining pending paper with exactly one dedicated Sub Agent. Read [the screening contract](references/screening-contract.md) before screening. A screening run covers every paper currently pending from the imported search result, with no arbitrary run-size limit. Retrieve and process it as consecutive waves of at most three concurrently running screening agents; never preload the complete result set into the main Agent. Use the model and reasoning effort in `[screening]`; the current baseline is `gpt-5.4-mini` with medium reasoning. Follow the fast screening loop until the database reports no pending paper from this run.
6. After the database reports no pending paper for the complete screening run, call `python -m autopaper.workflow finalize-screening`. This programmatically refreshes `workspace/review.md` and `workspace/STATUS.md` and creates a separate UTC-timestamped review under `[workflow].review_archive_dir` (default `workspace/reviews`). Present the archived file—not merely the mutable current review—for the user to inspect. Never substitute an ordinary `render` call for this completion step, and never overwrite or edit a historical archive. Verify only successful generation and compact aggregate counts; do not read the complete report into the main Agent. Stop before downloading so the user can inspect the original abstracts and tighten the selection. Do not show excluded papers unless the user explicitly requests an audit.
7. Apply the user's natural-language approvals or rejections to the database. Human review may reject an included or uncertain paper but must not silently promote an excluded paper.
8. Before subscription downloads, ask the user to close Clash and confirm that the dedicated Edge session may proceed. Supplementary material defaults to disabled.
9. Export only human-approved papers to `workspace/download_queue.jsonl`, run the production Edge adapter, perform the existing lightweight PDF validation, and record each outcome in the database. The current `scripts/windows/download_edge_test.bat` is a legacy validation launcher that still downloads supplementary material; do not use it for a production queue when `supplementary = false`. Pause until the production wrapper enforces this flag.
10. A successful PDF becomes `markdown_status = pending`. Do not call MinerU until the user supplies the final integration plan.

For status or resume requests, query compact aggregate counts and only the bounded rows needed for the next action, regenerate `workspace/STATUS.md` programmatically, and continue only the incomplete stage. Never dump the full database or report into the main Agent, and never repeat completed searches, screening decisions, or successful downloads unless the user explicitly requests a rerun.
