# AutoPaper

Operate inside the AutoPaper project. Treat the database selected by `[workflow].database` as the source of truth. The current `workspace/review.md`, timestamped review archives, `workspace/STATUS.md`, and their statistics are deterministic program output: never have the main Agent compose them from accumulated screening results or load their full contents into its context. Keep them synchronized at user-visible checkpoints, but do not add report inspection or redundant render calls between screening waves.

## Workflow

1. Read `config/config.local.toml`. Never print or copy API keys into reports, prompts, or logs.
2. Search with the existing OpenAlex pipeline. Import `candidates.jsonl` or `candidates.csv` with `python -m autopaper.workflow import`; do not read a large candidate file into the main Agent's context. Read [the screening database contract](references/screening-database.md) before importing.
3. By default, let the import command compare every candidate against the durable database by normalized full journal name plus title. During import, papers with no usable abstract are programmatically recorded as `uncertain` with the fixed missing-abstract reason and must never be sent to a Sub Agent. Report only compact counts: current candidates, existing matches, reused decisions, missing-abstract automatic decisions, and papers still requiring Sub Agents. The command programmatically places completed results in the current `review.md`. Never have the main Agent perform this matching or copy records. Use `--no-reuse` only when the user explicitly asks to ignore stored decisions and rescreen every current candidate; missing-abstract papers remain automatic `uncertain` even in that mode.
4. If the configured criteria and decision prompt do not match the profile stored in the selected database, or if multiple candidate databases/profiles are available and the intended one is not explicit, stop and ask the user whether to reuse one and which one. Never mix decisions produced under different prompts. A new prompt should normally use a new database path.
5. Screen pending papers in batches using `[screening].papers_per_agent` (currently 3), with at most `[screening].max_parallel_agents` concurrent Sub Agents (currently 3). Read [the screening contract](references/screening-contract.md) before screening. Use `python -m autopaper.workflow pending-batches` to retrieve the next bounded wave; each output line is one agent payload with shared criteria and up to three papers. Use the configured model and reasoning effort (currently `gpt-5.6-luna` / `low`). Each agent judges its papers independently and returns an array with one result per paper. The main Agent validates and records each result. Continue until no pending papers remain, unless the user asks to pause or limits the current scope. Never preload the full result set.
6. After the database reports no pending paper for the complete screening run, call `python -m autopaper.workflow finalize-screening`. This programmatically refreshes `workspace/review.md` and `workspace/STATUS.md` and creates a separate UTC-timestamped review under `[workflow].review_archive_dir` (default `workspace/reviews`). Present the archived file—not merely the mutable current review—for the user to inspect. Never substitute an ordinary `render` call for this completion step, and never overwrite or edit a historical archive unless the user explicitly requests a correction to that specific document. Verify only successful generation and compact aggregate counts; do not read the complete report into the main Agent. Stop before downloading so the user can inspect the original abstracts and tighten the selection. Project reviews must save all completed screening results: include, uncertain, and exclude, each with original title, original abstract (or an explicit missing-abstract marker), and the stored Chinese reason. Keep [workflow].review_include_excluded = true in both project and run-specific configurations; never silently override it or pass include_excluded=False when generating a review.
7. Apply the user's natural-language approvals or rejections to the database. Human review may reject an included or uncertain paper but must not silently promote an excluded paper.
8. Before subscription downloads, ask the user to close Clash and confirm that the dedicated Edge session may proceed. Supplementary material defaults to disabled.
9. Export only human-approved papers to `workspace/download_queue.jsonl`, run `python -m autopaper.edge_download` with the selected workflow config and queue, perform the existing lightweight PDF validation, and record each outcome in the database. This production adapter requires `supplementary = false` and downloads main PDFs only. `scripts/windows/download_edge_test.bat` is a legacy validation launcher that still downloads supplementary material; do not use it for production queues.
10. A successful PDF becomes `markdown_status = pending`. When the user requests Markdown conversion, read [the MinerU conversion contract](references/markdown-conversion.md), then use `python -m autopaper.mineru` with the same workflow configuration/database as the downloads. This uploads PDFs to the external MinerU service; download approval alone does not authorize conversion. Keep the token and personal conversion preferences in the Git-ignored `config/mineru.local.toml`, separate from existing search/screening settings. The script selects unfinished PDFs, saves remote task IDs, downloads Markdown plus images, and updates SQLite and STATUS programmatically. Do not read or rewrite complete Markdown documents in the main Agent context. Start with a single paper for a first-time test; run the remaining scope only when authorized.

For status or resume requests, query compact aggregate counts and only the bounded rows needed for the next action, regenerate `workspace/STATUS.md` programmatically, and continue only the incomplete stage. Never dump the full database or report into the main Agent, and never repeat completed searches, screening decisions, or successful downloads unless the user explicitly requests a rerun.

When the user asks to pause and receive an interim review, finish only the already active batches, record their successful results, and use `render_review` with `include_excluded=settings.review_include_excluded` and a new timestamped `partial-review.md` path scoped to the active run. Keep pending papers pending, preserve all existing review documents, and report completed and pending counts. Do not call `finalize-screening` or start another batch.
